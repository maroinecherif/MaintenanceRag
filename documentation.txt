 RAG (Retrieval-Augmented Generation) ?
 Le RAG (Retrieval-Augmented Generation) est une technique qui combine :
Recherche d’information + Intelligence artificielle (LLM)
👉 Concrètement :
1.	L’utilisateur pose une question en langage naturel
2.	Le système cherche des données pertinentes dans une base (documents, incidents, etc.)
3.	Il injecte ces données dans un prompt
4.	Un modèle IA (LLM) génère une réponse basée sur ces données

avantage du RAG :
👉 Sans RAG :
•	Tu dois faire des requêtes SQL complexes
•	Tu ne peux pas poser de questions naturelles
•	Tu dois connaître le schéma exact
•	Tu n’as pas de synthèse intelligente
👉 Avec RAG :
Tu peux poser :
“Quels incidents récurrents sur les pompes hydrauliques ?”
Et obtenir :
•	une synthèse
•	les causes fréquentes
•	les solutions utilisées
•	les sources (IDs incidents)
________________________________________
🚀 Les avantages du RAG
1. 🔍 Recherche intelligente
•	comprend le sens (pas juste mots-clés)
•	“perte de pression” ≈ “baisse pression”
________________________________________
2. 🧠 Réponses synthétiques
Au lieu de lire 20 incidents :
👉 le système te donne un résumé clair
________________________________________
3. 📚 Basé sur TES données
Contrairement à un LLM classique :
•	il ne répond PAS avec internet
•	il répond avec ta base interne
👉 donc :
•	fiable
•	traçable
•	auditable

Le RAG permet de connecter un modèle d’IA à une base de données interne.
On récupère les données pertinentes, on les injecte dans le prompt, et le modèle génère une réponse basée uniquement sur ces données, avec des sources.

Jour 3 — Embeddings + Ollama + Indexation
🎯 Objectif du Jour 3
Transformer les incidents (texte) en vecteurs numériques (embeddings) pour permettre une recherche sémantique.
🧠 Principe
Un embedding = représentation numérique d’un texte.
Exemple :
"perte de pression pompe"
→ [0.12, -0.45, 0.78, ...]
Ces vecteurs permettent de comparer le sens des textes.
